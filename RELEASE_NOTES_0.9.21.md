# Cloud Storage 0.9.21

Обновление Desktop Client, Server Manager, Core и виртуального диска Windows.
Телефонные приложения не изменены и не переизданы.

## Главное

- Веб-клиент встроен в Core: откройте адрес сервера и введите текущий динамический
  код из Manager. Доступны пространства, папки, загрузка/скачивание, просмотр
  текста и изображений, переименование и удаление с проверкой прав.
- В Manager появились кнопки открытия веб-клиента и копирования адреса.
- Исправлены mixed-case пути, вложенные папки, переименование, удаление через
  Проводник/PowerShell, пустые папки и задержка видимости записи виртуального диска.
- Исправлено подключение динамического устройства через zrok2 без лишнего пароля,
  распознавание новых публичных адресов, проверка готовности и управление процессом.
- Исправлено сохранение устаревшего LAN TLS-pin при переходе на публичный HTTPS.
- Запрет браузерного доступа теперь не блокирует Desktop Client и проверку туннеля.

## Безопасность и совместимость

Существующая SQLite обновляется миграциями; установщик сохраняет настройки и
перед миграцией делает резервную копию базы. TLS и проверки целостности не отключены.
Веб-сеанс хранится в HttpOnly cookie, на сервере — только отпечаток; предусмотрены
CSRF/Origin-проверки, истечение срока, выход и отзыв устройства.

## Установка

Четыре пользовательских файла: универсальный Server Installer, универсальный
Client Installer, архив Desktop Client и архив Server Manager. Установщики получают
последнюю либо выбранную версию из подписанного каталога. Два версионных Setup EXE
и два подписанных каталога — служебные файлы обновления.

## Честные границы проверки

Проверены автоматические тесты, настоящий смонтированный WinFSP-диск и веб-клиент
как локально, так и по публичному HTTPS через hosted zrok2: вход, загрузка,
скачивание и повторный вход после обновления страницы. В отдельном API-прогоне
256 КиБ переданы с совпадением SHA-256. Браузер и тестовый сервер работали на
одном компьютере, но внешний тест шёл через настоящий публичный frontend zrok2.
Первый `/enable` получил HTTP 500 провайдера, повторная попытка прошла.

Для сохранения адреса после рестарта zrok2 необходимо постоянное публичное имя;
ephemeral URL не является постоянным. Чистая Windows VM, отдельная внешняя сеть,
реальные Docker-контейнеры и Google OAuth/SMTP в этом выпуске не проверены.

Полный реестр причин, исправлений и ограничений: `docs/0.9.21-bug-register.md`.
