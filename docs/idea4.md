# Idea 4 — центр управления и Apple-приложения

Idea 4 реализована как единый слой Server Core. Desktop Manager, мобильный Manager и
API читают одно состояние, поэтому настройки не являются декоративными и не теряются
после закрытия интерфейса.

Релиз Idea 4 имеет версию **0.9.5** (сокращённо «9.5» в исходном ТЗ).

## Что работает

- 8 системных профилей: стандартный, ручной, автоматический, производительный,
  энергосберегающий, зеркало, SSD-кэш и рекомендуемый;
- простой интерфейс с сокращённым меню и подробный интерфейс со всеми разделами;
- базовый и расширенный режимы безопасности;
- 10 аварийных и 10 обычных шаблонов автоматизаций из разрешённых блоков;
- Telegram Bot API, SMTP email и HTTPS webhook; токены и пароли лежат отдельно от
  публичных настроек и никогда не возвращаются API;
- уведомление о переходе на батарею/ИБП и об оставшемся времени, если ОС умеет его
  определить;
- готовая аварийная автоматизация реагирует именно на потерю внешнего питания,
  предупреждает пользователя, ставит выключение через 60 минут и отменяет его при
  восстановлении питания. Системное выключение нужно отдельно разрешить в Manager;
- сон после настраиваемого простоя (20 минут по умолчанию), только после отдельного
  разрешения системной команды и только когда нет активных передач;
- Wake-on-LAN отправляет настоящий magic packet;
- плановые отчёты с выбором разделов: система, диски, хранилище, подключения,
  интернет, пользователи, передачи, диагностика, резервные копии и питание;
- контейнерные тестовые ячейки Docker/Podman с ограничениями CPU, RAM, рабочего
  диска, процессов, сети и времени. Выполнение команд прямо на хосте запрещено;
- при создании пользователя Core автоматически создаёт личное пространство,
  одноразовый код, файл `.cloud-access.json`, ссылку скачивания и при настроенном SMTP
  отправляет данные на указанный email;
- политика браузерного доступа через zrok: все вошедшие, только доверенные устройства
  или никто. Административный API через zrok по-прежнему не публикуется;
- поиск в помощи ведёт сразу в соответствующий экран Manager.

## Ограничения железа, которые нельзя обойти программой

Если ИБП не сообщает батарею операционной системе, Core честно показывает
`unknown` и не выдумывает оставшееся время. Спящий компьютер не может принять HTTP
запрос: для пробуждения по доступу нужно включить Wake-on-LAN в BIOS/UEFI, драйвере
сетевой карты и роутере. Без Docker или Podman ячейки сохраняются со статусом
`unsupported` и не запускаются небезопасным способом на хосте.

## Apple

Expo-конфигурация создаёт две отдельные универсальные программы для iPhone и iPad:
Mobile Client (`com.cloudstorage.mobile`) и Mobile Manager
(`com.cloudstorage.manager`). CI собирает обе Simulator-программы и снимает отдельные
скриншоты iPhone/iPad. Установка на физические устройства требует Apple Developer
подписи владельца проекта.

Дополнительно CI создаёт неподписанные IPA для Client и Manager. Их можно подписать
личной или корпоративной Apple-подписью и установить на iPhone/iPad; без подписи Apple
не разрешает установку приложения на физическое устройство.

На macOS PyInstaller создаёт `Cloud Storage Server Manager.app` и
`Cloud Storage Client.app`. Скрипт `scripts/package-macos.sh` упаковывает сервер и
клиент в отдельные DMG; Core входит в серверный образ. Подпись и notarization также
требуют сертификата Apple Developer ID и выполняются владельцем сертификата.

## Безопасность Idea 3

Гарантия Idea 3 сохранена: загрузка, докачка, восстановление и репликация вызывают
единое упрочнение файла. Управляемые данные становятся read-only и non-executable;
Core никогда не запускает пользовательские файлы. Произвольные сценарии допускаются
только внутри ограниченной контейнерной ячейки Idea 4.
