# Cloud Storage 0.10.8b5 — автоматическое обновление Windows

- Client и Server Manager проверяют подписанный каталог при запуске и автоматически
  скачивают и устанавливают новую версию, если режим обновлений ещё не был выбран.
- Установка ждёт завершения передач; после установки приложение запускается снова.
- Сохранённый ручной режим и выбранный канал сохраняются. Бета-сборка по умолчанию
  получает стабильные и тестовые обновления, стабильная — только стабильные.
- Каталог проверяется Ed25519, установщик — по размеру и SHA-256. Повреждённый
  или изменённый пакет не запускается. Неполная загрузка поддерживает докачку.
- Сетевые ошибки и отмена UAC оставляют приложение работающим. Отмена UAC больше
  не приводит к предварительной остановке серверного Core.
- Подсчёт активных серверных передач теперь учитывает записи вне страницы истории.

## Установка

Используйте Client Setup или Server Setup для Windows x64. При существующей
установке обновление сохраняет настройки и данные. Windows может запросить
разрешение администратора. Перезагрузка ПК автоматически не выполняется.

Один раз установите versioned Setup b5 из этого релиза. В b5 используется новый
отдельный канал каталогов v2: прежний приватный ключ недоступен, старые каталоги
не изменяются, поэтому старое приложение не обнаружит b5 автоматически.
После перехода следующие версии будут приходить через канал v2.
Если ранее был явно сохранён ручной режим, в разделе «Обновления» выберите
режим «Автоматически устанавливать при запуске».

## Границы проверки

Автоустановка относится к Windows Client и Server Manager. Android/iOS и отдельные
headless-службы не получают этот сценарий. Рабочая установленная служба пользователя
не используется для экспериментов. Тесты с подменённым запуском установщика не
являются реальной проверкой установки через UAC.

Это beta. Установщики не имеют Authenticode-подписи коммерческого издателя;
подпись каталога Ed25519 и контрольные суммы проверяются отдельно.
Минимум 60 МБ/с и 100–200 МБ/с через интернет не подтверждены.
Известный разрыв между публикацией файла и завершением upload-сессии при аварии
остаётся отдельной задачей; b5 не заявляет его исправление.
