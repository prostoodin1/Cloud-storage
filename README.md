# Cloud Storage Server

Домашний облачный сервер для Windows и Linux. Версия **0.7.2** завершает расширение безопасной серверной автоматизации перед финальным мобильным этапом из [Idea #003](https://github.com/prostoodin1/Cloud-storage/issues/3): правила получили расписание, события хранилища и устройств, новые встроенные действия, предварительную проверку и управляемый планировщик.

## Что уже работает в Alpha 0.3

- отдельное приложение Desktop Client для Windows/Linux;
- подключение по адресу сервера, одноразовому коду и паролю;
- безопасное ожидание ручного подтверждения устройства администратором;
- автоматическая проверка соединения и повторное подключение;
- просмотр разрешённых логических пространств и папок;
- постоянная очередь загрузки и скачивания с паузой, докачкой после обрыва и продолжением после перезапуска;
- индекс офлайн-каталога, обнаружение локальных/серверных изменений и безопасное разрешение конфликтов;
- интеграция офлайн-каталога с Проводником Windows и файловыми менеджерами Linux;
- системный трей, автозапуск и отдельный Windows Installer для Client;
- удаление файла в серверную корзину;
- шифрование токена устройства через Windows DPAPI;
- проверка TLS-сертификата по закреплённому SHA-256-отпечатку для будущего LAN-режима.
- общая вкладка «Помощь» в Manager и Client с вопросами, ответами и локальным помощником;
- SQLite-база знаний: помощник показывает источник, не выдумывает неизвестные ответы и сохраняет пробелы базы для последующего пополнения.
- отдельный клиентский HTTPS-вход Core для локальной сети, автоматический постоянный сертификат и закрепление SHA-256-отпечатка;
- поиск сервера в домашней сети и полное приглашение с адресом, кодом и отпечатком;
- административные маршруты и документация недоступны через LAN-вход.

Для работы на одном компьютере остаётся `http://127.0.0.1:8765`. LAN-доступ включается явно в расширенных настройках Manager → «Сеть» и использует отдельный порт `8766`. Незавершённые передачи хранят прогресс в SQLite и продолжаются с подтверждённого сервером смещения.

- программа не использует UPnP и не меняет роутер/firewall: рекомендуется VPN, прямое перенаправление одного порта настраивается вручную;

Для выдачи нового приглашения временно включите отдельный флаг подключения по коду; уже подтверждённым устройствам он не нужен.

## Как работает подключение человека

1. Администратор запускает ядро в Server Manager и создаёт пользователя с квотой.
2. Менеджер показывает одноразовый короткий код и QR, действующие 15 минут.
3. Человек вводит этот код в клиенте и задаёт пароль при первом подключении.
4. Устройство появляется у администратора со статусом «Ожидает».
5. После подтверждения устройство получает доступ к личному пространству. Повторно использовать код нельзя.

В Alpha 0.3 этот сценарий уже реализован в Desktop Client. Мобильное приложение начнётся после стабилизации настольного протокола.

## Подключение второго компьютера в локальной сети

1. В Server Manager переключитесь в расширенный режим и откройте «Настройки → Сеть».
2. Включите защищённое LAN-подключение и сохраните настройки: Core безопасно перезапустится.
3. В Windows разрешите входящие подключения только для частных сетей, если появится системный запрос.
4. Создайте пользователю код и отправьте полное приглашение либо откройте Client на втором компьютере и нажмите «Найти в сети».
5. При поиске вручную сверьте начало SHA-256-отпечатка с Server Manager перед вводом пароля. Полное приглашение уже содержит закреплённый отпечаток.

## Подключение из интернета

1. Установите актуальный zrok по официальной инструкции, получите приглашение zrok и один раз выполните `zrok enable` от имени учётной записи, под которой работает Core.
2. В Server Manager откройте расширенный режим → «Удалённый доступ», включите zrok и сохраните настройки. После запуска Manager покажет публичный HTTPS-адрес. Роутер и firewall менять не нужно.
3. Для нового устройства временно разрешите удалённое подключение по коду, создайте приглашение и после погашения кода снова выключите этот флаг.
4. В Desktop Client добавьте публичный HTTPS-адрес, дождитесь подтверждения устройства, введите логин и тот же пароль и нажмите «Войти через интернет».
5. Альтернативы остаются прежними: VPN либо отдельный прямой HTTPS-порт с ручной настройкой. Все внешние файловые запросы требуют интернет-сессию.

## Быстрый запуск из исходников

Нужен Python 3.11 или новее.

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[dev,build]"
.\.venv\Scripts\python -m cloud_storage
```

### Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev,build]'
.venv/bin/python -m cloud_storage
```

Ядро можно запустить отдельно:

```powershell
.\.venv\Scripts\python -m cloud_storage.core
```

Desktop Client запускается отдельно:

```powershell
.\.venv\Scripts\python -m cloud_storage.client
```

Интерактивная схема локального API после запуска доступна по адресу `http://127.0.0.1:8765/docs`. Административные маршруты требуют секрет менеджера и предназначены для Server Manager.

## Проверка и сборка

```powershell
.\.venv\Scripts\python -m pytest
.\.venv\Scripts\python -m ruff check .
.\scripts\build-installers.cmd
```

В Linux используйте `./scripts/build.sh`. Результаты находятся в:

- `dist/CloudStorageServerManager`;
- `dist/CloudStorageServerCore`;
- `dist/CloudStorageServerService` на Windows.
- `dist/CloudStorageClient`.
- `dist/CloudStorageDrive.exe` на Windows;
- два готовых установщика в `outputs`.

Автономная сборка не требует установленного Python на компьютере пользователя.

Оба Windows-установщика собираются одной командой
`powershell -ExecutionPolicy Bypass -File scripts/build-installers.ps1`. Для сборки нужны
Go 1.25+ и Inno Setup 6. Скрипт скачивает ровно WinFsp 2.1.25156 и принимает его только при
совпадении закреплённого SHA-256. Python, Go и Inno Setup на компьютере пользователя не нужны.

Манифесты публикации создаются `scripts/sign-update-manifest.py`. Закрытый Ed25519-ключ нельзя
добавлять в репозиторий или выпуск; приложение содержит только публичный ключ проверки.

```bash
./scripts/install-service.sh
```

Удаляющие службу сценарии сохраняют базу и файлы сервера. Windows-данные по умолчанию находятся в `%PROGRAMDATA%\CloudStorage`, Linux-данные — в `~/.local/share/cloud-storage`. Путь ядра можно переопределить через `CLOUD_STORAGE_CORE_DATA_DIR`.

Настройки интерфейса хранятся отдельно: `%LOCALAPPDATA%\CloudStorage\settings.json` в Windows или `${XDG_CONFIG_HOME:-~/.config}/cloud-storage/settings.json` в Linux.

Настройки Desktop Client и зашифрованный токен находятся в `%LOCALAPPDATA%\CloudStorageClient` в Windows или `${XDG_CONFIG_HOME:-~/.config}/cloud-storage-client` в Linux.

База вкладки «Помощь» хранится локально в `knowledge.db` рядом с настройками соответствующего приложения. Этот помощник не является облачной нейросетью и не передаёт вопросы, токены или файлы в интернет. В дальнейшем поверх той же базы можно подключить необязательную генеративную модель с явным согласием администратора.
