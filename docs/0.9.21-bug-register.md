# 0.9.21 — реестр найденных ошибок и границы проверки

Исходная версия: 0.9.20, commit `1409e25`. Проверки выполняются на Windows
в изолированных каталогах и на отдельных портах. Установленная служба и её
пользовательские данные не меняются. Android исключён из этого обновления.

## Исправления

| № | Подтверждённая проблема | Исправление и проверка |
|---|---|---|
| 1 | В браузере корень сервера возвращал JSON, интерфейса файлов не было | Встроенный HTML/JS-клиент: динамический код, пространства, папки, загрузка, скачивание, просмотр текста и изображений, переименование, удаление. Ручной прогон в браузере и API-тесты |
| 2 | Интернет-вход динамического устройства ошибочно требовал старую парольную сессию | Сохраняется метод pairing устройства; миграция допускает passwordless только при подтверждённой записи аудита. Тест повторного подключения и отзыва |
| 3 | После перехода с LAN на публичный HTTPS Client восстанавливал старый TLS-отпечаток | Пустой pin публичного адреса больше не заменяется старым локальным. Проверка доверенного HTTPS остаётся включённой |
| 4 | zrok2 сообщал bare hostname `*.shares.zrok.io`, который не распознавался | Парсер официального текстового/JSON-вывода, HTTPS по умолчанию. URL из ошибок/документации не принимаются за рабочий frontend |
| 5 | Состояние zrok «online» не означало доступность именно этого Core | Проверка публичного HTTPS `/v1/health` и уникального probe ID, повторные проверки, сброс устаревшего адреса, перезапуск зависшего процесса |
| 6 | Установка/подключение zrok блокировали UI; повторный запуск и остановка оставляли неверное состояние | Фоновые задачи, headless CLI, один контролируемый дочерний процесс, изолированный профиль, корректная остановка и повторная попытка |
| 7 | Клиентские запросы могли попадать на HTML-уведомление zrok | Официальный заголовок API во всех Desktop API/upload/download и Go-диске; это не отключает браузерные предупреждения |
| 8 | «Браузер: никто» блокировало весь туннель, health и Desktop Client | Политика отделена от транспорта; web-cookie проверяется отдельно. Запрет браузера не выключает Desktop API |
| 9 | Переименование/удаление с диска давало 404 для mixed-case имён и вложенных папок | Каждый компонент пути разрешается по реальному имени на Core; неоднозначные имена, отличающиеся только регистром, отклоняются |
| 10 | Copy/Close возвращались раньше появления файла на сервере | Синхронизация на Cleanup, до отложенного WinFSP Close; отдельный статус ошибки сохранения, локальный кэш не удаляется при сбое |
| 11 | Flush дескриптора только для чтения мешал удалению, включая PowerShell | Не выполняется ненужный Flush для неизменённых файлов. Реальные delete/rename через смонтированный T: проходят |
| 12 | Удаление пустой папки возвращало WinError 38 | `Readdir(-1)` возвращает пустой список без EOF, как требует контракт Go |
| 13 | Fallback constrained-write зависимости мог выйти за границы буфера у EOF | Собственная реализация Append/ConstrainedWriteAt с блокировкой и ограничением размера; Go-регрессия |
| 14 | Отказ прав записи мог обнаружиться только после закрытия файла | Проверка capability перед write/create/delete, помимо обязательной проверки на Core |
| 15 | Встроенный браузер не поддерживает JS `prompt()` | Собственные доступные диалоги создания, переименования и подтверждения удаления |
| 16 | Установщик игнорировал ошибки копирования резервной базы/настроек/ключей | При ошибке копирования обновление прекращается с понятной причиной |
| 17 | PyInstaller подхватывал несовместимую ICU DLL из Poppler в PATH сборочного окружения; QtCore падал ещё до запуска Client | Все сборки выполняются с изолированным PATH системных библиотек; проверяется запуск именно упакованного Client |

## Защита нового веб-доступа

- Сеанс: случайный секрет в HttpOnly/SameSite=Strict cookie, Secure вне loopback;
  в SQLite только HMAC-отпечаток, срок 30 дней. Код и device bearer token не
  сохраняются в JavaScript/localStorage.
- Origin и CSRF проверяются для изменяющих запросов. Manager API не принимает
  web-cookie и остаётся скрытым на внешнем listener.
- Каждая операция повторно проверяет устройство, пользователя и права пространства.
  Выход аннулирует сеанс; отзыв устройства/отключение пользователя действует сразу.
- Загруженный HTML показывается только как текст; SVG и исполняемые документы
  не вставляются в DOM. CSP, запрет iframe, no-store и no-referrer.

## Известные ограничения, не выдаваемые за исправленные ошибки

- У ephemeral zrok меняется URL после перезапуска. Для постоянного адреса нужно
  зарезервировать имя в аккаунте zrok2 и указать его в Manager. Центральный сервис
  поиска серверов не добавлялся.
- Бесплатный hosted zrok может показать свою страницу `Visit Share`. Это страница
  провайдера до Core, а не наш интерфейс; TLS-предупреждения не обходились.
- Ранее настоящий публичный API-тест прошёл (pairing, 256 КиБ, SHA-256,
  автоподключение и отзыв). Первая повторная попытка `/enable` получила HTTP 500
  от zrok2; вторая прошла. После обычного нажатия `Visit Share` браузер открыл
  встроенный веб-клиент через публичный HTTPS. Подтверждены вход по CS3,
  загрузка HTML-файла, появление файла в списке, событие скачивания браузера
  и сохранённый вход после перезагрузки страницы. Ни сертификатные предупреждения,
  ни cookies/zrok-заголовки браузера вручную не подменялись.
- Отдельная физическая интернет-сеть и чистая Windows VM недоступны. Docker
  отсутствует; реальные контейнеры не проверены. Google OAuth/SMTP без нового
  настроенного аккаунта не проверялся. Android не менялся и не тестировался.

## Воспроизводимые проверки

- `python -m pytest` — полный Python-набор.
- `go test ./...` в `drive_windows` и `core_go`.
- `python scripts/verify-mounted-drive.py --drive-exe <абсолютный EXE> --letter T`
  — отказывается трогать занятую букву; создаёт временный Core/профиль; проверяет
  hash/read/create/rename/delete/mixed-case/empty-directory; останавливает стенд.
- `python scripts/serve-web-qa.py` — отдельный веб-стенд на свободных портах,
  автоматически завершается через 15 минут.
- `scripts/verify-package.ps1 -Dist <папка сборки>` — запуск упакованного Client,
  Go Core smoke, API/HTML/JS из упакованного совместимого Core, остановка по API,
  наличие модуля виртуального диска и отсутствие чужой ICU. Manager и Container
  Manager требуют UAC: без повышения прав проверяется состав их пакетов; реальные
  конструкторы всех трёх окон отдельно проходят `--smoke-test` из исходников.
