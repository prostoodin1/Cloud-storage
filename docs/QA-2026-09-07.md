# Проверка Cloud Storage — 7 сентября 2026

Проверена исправленная сборка, подготовленная для выпуска 0.9.23 на основе
коммита 0.9.22 `519336bf980055bd8fd305fb13c82bb53fafd401`. Первичный аудит выполнен

Во время аудита существующие релизные файлы и установленная серверная служба
не заменялись. Android-приложения не менялись.

## Найденные и исправленные ошибки

1. **Постоянный установщик скрывал выбор ярлыков.** Он запускал внутренний Setup
   с `/VERYSILENT`, поэтому пользователь не видел страницу дополнительных задач.
   Теперь установка из постоянного установщика интерактивная. В обоих Setup есть
   необязательный ярлык рабочего стола, по умолчанию не выбранный. Автоматическое
   обновление внутри приложения сохраняет прежний тихий режим. Проверка подписи
   каталога, размера и SHA-256 пакета не отключалась.
2. **Сохранённые буквы дисков менялись после перезапуска.** Резервирование старой
   одиночной буквы конфликтовало с назначениями пространств того же профиля.
   Например, сохранённые S:/T: превращались в T:/U:. Резервная одиночная буква
   теперь учитывается только при отсутствии назначений по пространствам.
   Новый тест сначала воспроизвёл ошибку, затем прошёл три цикла сохранения и
   повторного чтения без изменения S:/T:.
3. **Отклонённый запрос остановки мог завершить Go-супервизор.** Локальный
   административный прокси планировал остановку после любого POST на shutdown,
   даже если Core ответил 401, 403 или 503. Теперь остановка разрешается только
   после ответа 200 от Core. Новый HTTP-тест воспроизвёл все три ошибочных случая
   до исправления и проверил отказ/разрешённую остановку после него. Это проблема
   локального административного прокси, не доказательство удалённой атаки.

### Собранные приложения и сервер

Изолированный упакованный Core проверен по HTTP: pairing, создание папки,
загрузка/скачивание, размер файла и квота, вход браузерной сессии того же человека,
отдельная папка и загрузка через веб-API, публичная ссылка, ответ диагностики,
архивация и восстановление пространства. Второй человек не получил доступ к
чужому личному пространству. После корректного завершения и запуска Core с той
же тестовой базой сохранились токены, файлы и браузерная сессия.

В этом прогоне файловые операции исполнял упакованный совместимый Python Core.
Go EXE прошёл smoke-тест, а новый прокси — отдельные Go-тесты. Это не равно
полной проверке установленной Windows-службы с новым Go-супервизором.

### Виртуальный диск

Проверен драйвер из новой сборки, настоящая буква W: в Windows, отдельный Core и
только искусственные данные. Windows показала 3 ГиБ, затем 5 ГиБ после изменения
квоты, а не 8 ТБ. Свободное место уменьшалось при записи и восстанавливалось при
удалении. Чтение сразу после закрытия файла совпало по SHA-256. Удаление файла
проверено обычным файловым вызовом и PowerShell, затем удалена папка.
Архивация пространства размонтировала диск; восстановление сохранило тестовый
файл. После прогона W: отсутствует, рабочая служба осталась запущена.

### Реальный браузер

В отдельной вкладке на локальном тестовом Core выполнены:

- вход динамическим кодом существующего тестового человека;
- создание папки «Проверка 7 сентября» и переход в неё;
- загрузка `sample-upload.txt` через выбор файла, отображение размера 37 байт;
- предпросмотр с правильным содержимым;
- нажатие скачивания с получением браузерного события загрузки;
- перезагрузка страницы с сохранением входа;
- повторный вход в папку и обновление списка без выбрасывания из неё.

В полученном журнале браузера не было ошибок и предупреждений. Скачивание в UI
подтверждено событием браузера; путь к сохранённому браузером файлу инструмент не
предоставил, поэтому хеш именно этой копии не проверен. Побайтовое совпадение
загрузки/скачивания проверено отдельно через API и настоящий виртуальный диск.

### Установщики

Оба постоянных EXE собраны и запущены в smoke-режиме. Тесты настоящих Qt-окон
проверили выбор последней/старой версии и передачу выбранного пакета в
интерактивный запуск Setup. Само скачивание и привилегированный запуск в этом
Qt-тесте заменены тестовыми вызовами. Оба автономных Setup успешно собраны Inno
Setup. Для окончательного выпуска они пересобираются с версией ресурсов 0.9.23.

## Что ещё не подтверждено

- **Чистая Windows/виртуальная машина:** установка, выбор ярлыков через реальный
  мастер, UAC, установка зависимостей, обновление работающей службы, удаление и
  повторная установка. Сборка и тест вызова мастера не заменяют этот сценарий.
- **Новый Go-супервизор как установленная служба:** второй экземпляр не запустился
  рядом с работающей службой из-за глобальной блокировки экземпляра
  (`create core mutex: Access denied`). Рабочая служба не останавливалась,
  блокировка не обходилась. Нужна отдельная Windows-среда либо согласованное
  окно замены/перезапуска установленной службы с резервной копией.
- **Интернет из другой сети:** сегодня проверен локальный браузер, не внешний
  клиент через zrok2. Это не подтверждает доступность сайта из интернета.
- **Реальные внешние интеграции:** отправка Gmail/SMTP, Docker/SSH, публикация и
  скачивание нового релиза с GitHub не выполнялись в этом прогоне. Наличие
  модульных тестов не означает успешную проверку этих сервисов вживую.
- **Длительная работа и сбои оборудования:** многочасовая нагрузка, внезапное
  отключение питания и физический отказ накопителя не моделировались.
