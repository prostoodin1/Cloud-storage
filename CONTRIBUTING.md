# Участие в разработке

Спасибо за помощь Cloud Storage. Проект находится в beta; сохранность данных,
совместимость протокола и понятное восстановление после ошибки важнее числа функций.

## С чего начать

- Для ошибки используйте [Bug report](https://github.com/prostoodin1/Cloud-storage/issues/new?template=bug_report.yml).
- Для предложения используйте [Feature request](https://github.com/prostoodin1/Cloud-storage/issues/new?template=feature_request.yml).
- Уязвимости сообщайте по [SECURITY.md](SECURITY.md).
- Среда разработки и команды проверки описаны в [docs/development.md](docs/development.md).

Перед крупным изменением интерфейса, протокола, базы или формата обновлений
опишите проблему и ожидаемый результат в issue. Небольшое исправление можно
сразу прислать как pull request.

## Изменения и проверки

1. Создайте отдельную ветку от актуального `main`.
2. Ограничьте изменение одной понятной задачей. Сохраняйте совместимость
   существующих профилей, токенов, очередей и баз; для миграции нужен сценарий восстановления.
3. Запускайте проверки затронутого компонента. Добавляйте регрессию, если она
   воспроизводит реальную ошибку; для исправления текста достаточно проверки ссылок.
4. В PR объясните проблему, итоговое поведение, проверку и оставшиеся ограничения.
   Для интерфейса приложите изображения с указанием масштаба и размера окна.

В сетевых изменениях указывайте размер файла в байтах, направление передачи,
маршрут, RTT/ограничение канала, число устройств, повторы и проверку SHA-256.
Разделяйте МБ/с и Мбит/с. Стенд на одном ПК не заменяет реальный интернет между устройствами.

## Данные и лицензии

Не добавляйте пользовательские файлы, базы, токены, приглашения, приватные ключи,
реальные адреса доступа или необезличенные журналы. Тестовые данные создавайте
в отдельных временных каталогах; тесты не должны менять установленную службу.

Оригинальный код проекта распространяется под [MIT](LICENSE). Сохраняйте
авторство и условия стороннего кода; новые зависимости сопровождайте ссылкой
на источник и сведениями о лицензии. См. [third-party notices](THIRD-PARTY-NOTICES.md).

Следуйте [правилам общения](CODE_OF_CONDUCT.md). Срок ответа и принятие PR не гарантируются.
