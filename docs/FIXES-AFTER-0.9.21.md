# Исправления после 0.9.21 — проверка 4 сентября 2026

Статус: исправления включены в выпуск **0.9.22**. Установленная на тестовом
компьютере 0.9.21 во время подготовки выпуска не изменялась.
Мобильные приложения не затрагивались.

В `output/0.9.22` находятся ровно четыре файла: два автономных Setup EXE
версии 0.9.22 и два ZIP-архива приложений. Они устанавливают именно эту сборку.
Для GitHub подготовлены также универсальные онлайн-установщики: они выбирают
последнюю или указанную пользователем версию из подписанного каталога обновлений.
Старые файлы 0.9.21 в корне `output` сохранены.

## Причины и исправления

- Client каждые три секунды заново заполнял список пространств и обнулял путь.
  Теперь текущая папка и выбранный файл сохраняются. Запоздалый ответ другого
  запроса не меняет текущий список; одинаковые незавершённые запросы объединяются.
- Адаптер WinFSP наследовал постоянную ёмкость 8 ТБ из библиотеки. Теперь ёмкость
  равна квоте пространства в Manager, занятое место вычисляется Core, свободное
  место обновляется во время работы и не становится отрицательным.
- Код «Новый человек» создавал независимого пользователя при каждом первом входе.
  Теперь Manager позволяет выдать подписанный пяти­минутный код существующему
  человеку: браузер и другие компьютеры получают те же пространства и права.
  В клиенте остаётся одно поле кода. Старые коды поддерживаются; для новой привязки
  по пользователю надо обновить и Core, и Desktop Client.
- Снятие права просмотра теперь полностью отзывает доступ, даже если другие
  флажки остались включены. Сервер проверяет права при прямых API-запросах,
  завершении загрузки и использовании публичной ссылки. Чужие личные пространства
  недоступны. Последняя отозванная буква диска больше не остаётся в настройках.
- В Manager: «Диски → Логические пространства → Удалить виртуальный диск».
  Удаление отключает доступ, отзывает ссылки и убирает диск в архив. Физические
  файлы сохраняются; восстановление доступно через «Архив». В карточке личного
  диска указан владелец и есть переход к его квоте. Это не очистка накопителя.
- Веб-интерфейс отбрасывает устаревшие ответы, корректно очищает доступ при
  отказе авторизации и показывает фактическую квоту/занятое место. Manager отдельно
  показывает, является адрес сайта локальным или настроенным для интернета.
- Миграция SQLite добавляет `spaces.archived_at`, сохраняя пользователей,
  токены, файлы и предыдущие настройки.

## Что НЕ подтверждено

На установленном сервере HTTP-страница по localhost открывается, но zrok отключён,
процесс туннеля не работает, публичный URL отсутствует. Поэтому доступ к реальному
сайту **из другой сети не проверен и не заявляется рабочим**. Нужен адрес,
который открывает пользователь, и настроенный интернет-вход. Настройки production,
служба и настоящие файлы пользователей во время проверки не изменялись.

Не проводились новые живые проверки SMTP/Gmail, Docker/SSH, установки обновления
поверх пользовательской системы или мобильных приложений. Прохождение тестов
не означает проверку абсолютно всех интеграций сервера в реальной среде.
