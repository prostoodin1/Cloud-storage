# Аудит Cloud Storage 0.10.8 beta 1 — 13 октября 2026

## Итог

Основной локальный файловый тракт работает: pairing, пользователи, изоляция личных пространств, создание папок, загрузка, скачивание, браузерная сессия, публичная ссылка, перезапуск Core и настоящий WinFsp-диск прошли проверку.

Перед следующим публичным выпуском необходимо исправить две серьёзные проблемы безопасности: отсутствие отдельного rate limit для веб-входа при разрешённых слабых паролях и отсутствие Authenticode-подписи у Windows EXE.

## Статус исправлений

- `HIGH-1` исправлена в исходниках: отдельные лимиты по учётной записи и источнику, шестая попытка за пять минут получает HTTP 429; добавлен регрессионный тест.
- `HIGH-2` подготовлена технически: release-сборка умеет подписывать и проверять все Windows EXE через Authenticode. Для фактической подписи нужен сертификат и `CLOUD_STORAGE_SIGN_CERT_THUMBPRINT`.
- `MEDIUM-1` исправлена в сборке: версия Go Core передаётся из `cloud_storage.__version__` через linker flags и проверяется сразу после компиляции.
- `MEDIUM-2` исправлена: полный package QA проходит в Windows PowerShell 5 и PowerShell 7.
- `MEDIUM-3` подготовлена: добавлены Dependabot-конфигурация и CodeQL workflow; они начнут работать после публикации изменений в GitHub.

## Найденные проблемы

### HIGH-1 — веб-вход допускает неограниченный перебор пароля

Маршрут `POST /v1/web/login` доступен через внешний listener, но не использует `remote_login_limiter`. Глобальная граница допускает до 600 внешних запросов в минуту и не является защитой конкретной учётной записи.

Отдельная проверка отправила 12 неправильных паролей подряд. Все 12 запросов дошли до проверки учётных данных и вернули `403 invalid username or password`; сервер ни разу не вернул `429`.

Риск особенно высок, потому что текущий продукт сознательно разрешает пароль длиной в один символ. Это позволяет удалённый подбор пароля и создаёт возможность CPU-DoS дорогими проверками Argon2id.

Рекомендуемое исправление:

- применять отдельный лимит по комбинации нормализованного логина и сетевого источника;
- добавить общий лимит для одного логина независимо от IP;
- ввести экспоненциальную задержку или кратковременную блокировку после серии ошибок;
- возвращать одинаковый ответ для существующего и несуществующего логина;
- записывать начало атаки в аудит без сохранения пароля;
- для Cloudflare/zrok учитывать, что backend может видеть один loopback-адрес для всех пользователей, поэтому нельзя полагаться только на `request.client.host`.

### HIGH-2 — опубликованные Windows-программы не имеют Authenticode-подписи

Проверены постоянные установщики и версионные Setup EXE. Для всех `Get-AuthenticodeSignature` вернул `NotSigned`.

Подписанный Ed25519-каталог защищает обновление после установки, но не позволяет Windows или новому пользователю проверить издателя первоначально скачанного EXE. Это вызывает предупреждения SmartScreen и оставляет риск подмены при распространении файла вне официальной страницы GitHub.

Рекомендуемое исправление:

- приобрести сертификат code signing и подписывать все EXE/MSI до формирования SHA-256 и каталога обновлений;
- проверять подпись в release workflow;
- публиковать имя подтверждённого издателя на странице скачивания.

### MEDIUM-1 — Native Go Core сообщает старую версию

Исходник `core_go/runtime.go` содержит `coreVersion = "0.10.4"`. Бинарник из релиза отвечает на `--version` значением `0.10.4`, хотя весь выпуск имеет версию `0.10.8b1`.

Функциональный `/v1/health` возвращает версию Python compatibility engine, поэтому пакетный тест не замечает рассинхронизацию. В журналах и диагностике пользователь может увидеть неправильную версию ядра.

Рекомендуемое исправление: передавать версию в Go через `-ldflags -X` из единого источника и проверять `--version` в CI.

### MEDIUM-2 — release QA-скрипт несовместим с Windows PowerShell 5

`scripts/verify-package.ps1` сохранён как UTF-8 без BOM и содержит русский текст. При запуске штатным `powershell.exe` 5.1 файл неправильно декодируется и падает с ParserError на строке проверки веб-страницы. В PowerShell 7 тот же сценарий проходит полностью.

Рекомендуемое исправление: либо официально запускать скрипт только через `pwsh`, либо сохранить совместимые PowerShell-скрипты как UTF-8 with BOM и добавить CI-проверку обоими движками.

### MEDIUM-3 — автоматическое сканирование зависимостей и кода не включено

GitHub API сообщил, что Dependabot alerts отключены, а Code Scanning не имеет ни одного анализа. Secret Scanning не показал открытых предупреждений.

Рекомендуемое исправление: включить Dependabot alerts/updates и CodeQL для Python, Go и JavaScript/TypeScript.

### LOW-1 — будущая несовместимость тестового стека

Все Python-тесты выводят `StarletteDeprecationWarning`: использование `httpx` через `starlette.testclient` устаревает, предлагается переход на `httpx2`.

Сейчас это не ломает продукт. Следует обновить совместимые версии FastAPI/Starlette/httpx до того, как предупреждение станет ошибкой.

### AUDIT-GAP-1 — исходные Go-тесты не удалось повторить на этой машине

В системе отсутствует Go toolchain, поэтому `go test ./...` для `core_go` и `drive_windows` не запускался. Это не падение тестов и не подтверждённая ошибка кода.

Компенсирующая проверка: готовые `CloudStorageServerCore.exe` и `CloudStorageDrive.exe` прошли smoke-test, функциональный пакетный сценарий и реальное монтирование WinFsp.

## Что этот аудит не подтверждает

- работу из другой реальной интернет-сети через живой Cloudflare/zrok-туннель;
- длительную работу под нагрузкой и с несколькими одновременными клиентами;
- физический отказ HDD/SSD во время записи;
- восстановление после отключения питания;
- чистую установку и обновление на отдельной виртуальной машине Windows без инструментов разработчика;
- актуальные мобильные приложения, которые относятся к более ранней линии;
- отсутствие неизвестных уязвимостей — независимого security audit и fuzzing не проводилось.

## Приоритет перед следующим релизом

1. Закрыть перебор `/v1/web/login` и добавить регрессионные тесты `429`.
2. Настроить Authenticode-подпись Windows-пакетов.
3. Синхронизировать версию Native Go Core.
4. Починить PowerShell 5 или закрепить обязательный `pwsh`.
5. Включить Dependabot и CodeQL.
6. Повторить чистую установку и интернет-тест на отдельной Windows VM.
